## Findings and disposition

**1. The unregistered-source warning fired on a registered, compiling source.** `registered` held case-sensitive resolved paths while `readdirSync` returns the real on-disk name. On Windows and macOS a manifest entry of `phases/Phase-01.yaml` against a file named `phase-01.yaml` loads, compiles, and contributes its sprints, and was still reported as unregistered. The warning's single claim was therefore false, and following its advice would add a duplicate registry entry. `samePath` in `roadmap-source-migration.ts` already did the right thing. **Applied:** a `comparablePath` helper folds case on win32 and darwin, with a test registering a differently-cased path.

**2. The mismatch message pointed at a changelog this repo does not have.** Ticket S267.5-4's own rationale is that there is no CHANGELOG file, which is why `docs/upgrading.md` exists. **Applied:** the message names that file.

**3. The upgrade note overclaimed, and the commit body repeated it.** "A projection written by either version compares equal to one written by the other" is false for a trailing-zero canonical id: 1.64.1 wrote `458.1` for an authored `"458.10"`, the shim maps that to `"458.1"`, and drift is correctly still reported. That id shape is the reason canonical sprint identity exists. Separately, "the half that helps a pinned CI" only holds when the pin is the newer binary. **Applied:** both limits are now stated plainly in the doc.

**Cosmetic, also applied:** a directory named `nested.yaml` was reported as a source; the scan now uses `withFileTypes`. The warning printed a cwd-relative path where the registry wants source-root-relative, so the advice handed the reader the wrong string.

## What the reviewer could not break

Sixteen probe cases against `roadmapProjectionMatches` all landed correctly. Everything that should be drift is drift: `[1]` vs `["01"]`, `[1]` vs `["1.0"]`, sprint `id` 2 vs `"2"`, phase `sprints` numbers vs strings, `sprint_keys`, key reordering, duplicate keys, a unicode escape against a literal, a BOM, and a four-space reindent. The canonical round-trip precondition holds for real generated bytes on both sides, because `stripRoadmapProjectionMarker` re-serialises through `JSON.stringify(x, null, 2)`. A real `v1.64.1` projection compares equal to a 2.x one built from the same sources, in both directions, and a CRLF checkout still matches.

Both self-inflicted regressions were judged genuinely fixed rather than masked. The formatting guard is sound by construction: if both sides round-trip to canonical, equal parsed values imply identical bytes.
